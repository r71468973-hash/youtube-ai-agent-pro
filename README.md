# youtube-ai-agent-pro
AI-powered YouTube Automation Agent that creates video scripts, generates AI voiceovers, produces videos and thumbnails, and uploads videos to YouTube after user approval.

## AI Video Studio

A self-hosted dashboard that turns a text story into a narrated, captioned video and uploads it to YouTube **only after you approve it**.

| Feature | How it works |
|---|---|
| Story to video | Story is split into scenes (Anthropic if a key is set, otherwise sentence splitting), then rendered with ffmpeg |
| Hindi and English voiceover | ElevenLabs, OpenAI or Google Cloud TTS (first key found, or your choice) |
| Shorts and long videos | 1080x1920 (9:16) or 1920x1080 (16:9) |
| Subtitles and music | Burned-in captions (Devanagari supported); built-in ambient beds or your own uploads, auto-ducked under the voice |
| YouTube | Google OAuth 2.0 (PKCE, offline access); resumable upload |
| Approval gate | Videos stop at **Awaiting your approval**. Upload needs an explicit approve action with a confirmation box; a failed upload consumes the approval |
| Cloud storage | Any S3-compatible bucket (Cloudflare R2, AWS S3, Backblaze B2, Supabase, MinIO) |
| API keys | Encrypted at rest (AES-256-GCM), write-only in the UI, never returned by the API |
| 3D animation | Consistent animated 3D characters, dialogue, lip-sync, camera moves (see below) |
| Dashboard | Mobile-first, bottom tab bar on phones, light and dark mode |

No npm dependencies. Requires Node 20+ and `ffmpeg`/`ffprobe`.

### Run

```bash
cp .env.example .env        # optional; set at least ADMIN_PASSWORD
export $(grep -v '^#' .env | xargs)
npm start                   # http://localhost:3000
npm test                    # unit + provider tests, then end-to-end test (renders real videos, incl. 3D)
```

If `ADMIN_PASSWORD` is not set, one is generated and saved to `data/.admin_password`.

### Docker

```bash
docker build -t ai-video-studio .
docker run -p 3000:3000 -v aivideo-data:/app/data -e ADMIN_PASSWORD=change-me -e APP_SECRET=$(openssl rand -hex 32) ai-video-studio
```

This needs a long-running server with ffmpeg and a persistent disk (a VPS, Fly.io, Railway, Render). It will **not** work on serverless hosts such as Vercel or Netlify.

### 3D animation (animated-3d mode)

Choose **Video style: 3D animated** when creating a video. Each line is performed by consistent 3D cartoon characters (same look in every scene) that walk, run, jump, wave, idle, and show happy, sad, surprised or angry expressions. Characters speak with timed lip movement that follows each voice-over line.

- **Story format:** write dialogue as `Name: line` (or `नाम: संवाद`). Add `[F]` or `[M]` after the name to set the voice gender, e.g. `Priya [F]: Hello`. Other sentences are narration, spoken by a voice-over while the main character acts. Actions and expressions come from keywords in each line (a heuristic, not story understanding).
- **Renderer:** the default `local-3d` provider runs headless Chrome/Chromium with three.js (vendored, MIT, in `lib/animation/stage/vendor`). It is free, needs no API key, and renders every frame on this server.
- **Optional paid provider:** `external-http` calls any video API that follows the job contract in `lib/animation/external.js`, using `VIDEO_API_KEY`. It has been tested only against a mock server. No specific vendor is integrated or verified.
- **Requirements:** Chrome or Chromium (set `CHROME_PATH` if it is not in a standard location). The Docker image installs chromium. Rendering is CPU-heavy: expect minutes per minute of video at 1080p. Set `RENDER_3D_SCALE=0.5` to render faster at lower resolution.
- **Limits:** characters are procedural primitives, not sculpted models. Lip-sync is timed to the voice-over length, not to phonemes. Without a TTS key the animation has no voice and says so.

### Connect YouTube

1. In Google Cloud Console enable **YouTube Data API v3** and create an OAuth client (type *Web application*).
2. Add the redirect URI shown in **Settings > YouTube** (`BASE_URL` + `/auth/google/callback`). Set `BASE_URL` to your public HTTPS address in production.
3. Paste the client ID and secret in **Settings > API keys**, then press **Connect YouTube**.

Note: uploads from unverified Google API projects are forced to *private* by YouTube until the project passes an API audit. Uploads are labelled as AI-generated by default (toggle in Settings).

### Cloud storage

Cloudflare R2 (S3-compatible) is set with Railway environment variables. Never put these values in code or in git:

- `R2_ACCOUNT_ID`: your Cloudflare account ID (the endpoint is built from it)
- `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`: an R2 API token with Object Read & Write on the bucket
- `R2_BUCKET_NAME`: the bucket, `youtube-ai-agent-storage`
- `R2_ENDPOINT` (optional): `https://<account>.r2.cloudflarestorage.com`, if you do not set `R2_ACCOUNT_ID`

Each finished video is uploaded under `YYYY/MM/DD/<videoId>/` with `video.mp4`, `thumb.jpg`, `voice.m4a`, `subtitles.ass` and `metadata.json`. A file counts as saved only after the bucket confirms it at the same size. Open the **Cloud** tab to test the connection, see usage against the 10 GB free tier, read upload errors, and delete old files.

If the R2 variables are missing or the bucket fails, videos stay on the server and the video shows a warning that says it is NOT in the cloud. The older Settings page (S3-compatible endpoint plus vault keys) still works when no R2 variable is set.

### Security notes

- Single-owner login, signed HttpOnly SameSite cookies, CSRF token on every write, login throttling, strict CSP.
- Set a stable `APP_SECRET` (16+ chars) in production. Changing it makes stored keys unreadable.
- Run behind HTTPS. Never commit `data/` or `.env` (both are git-ignored).
